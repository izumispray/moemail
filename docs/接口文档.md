## 认证方式

### 方式一：Session 认证

通过 Web UI 登录后自动携带 Session Cookie，适用于浏览器访问。

### 方式二：API Key 认证

在请求头中携带 API Key，适用于程序化调用：

```
X-API-Key: mk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

API Key 可在管理面板中创建，有效期为 1 年。

## 邮箱管理

### 创建邮箱

创建一个新的临时邮箱地址。

```
POST /api/emails/generate
```

**请求体：**

```json
{
  "name": "myemail",        // 可选，邮箱名称（不传则随机生成）
  "domain": "example.com",  // 必填，使用的域名
  "expiryTime": 5400000     // 必填，过期时间（毫秒），此例为 90 分钟；0 = 永不过期
}
```

`expiryTime` 支持任意非负安全整数毫秒值。`0` 表示永不过期，原有预设值保持兼容，例如：

| 值 | 含义 |
|---|------|
| `3600000` | 1 小时 |
| `86400000` | 24 小时 |
| `259200000` | 3 天 |
| `5400000` | 自定义 90 分钟 |
| `0` | 永不过期 |

**响应：**

```json
{
  "id": "uuid",
  "email": "myemail@example.com"
}
```

**错误响应：**

| 状态码 | 说明 |
|--------|------|
| `403` | 已达到最大邮箱数量限制 |
| `400` | 无效的过期时间或域名 |
| `409` | 邮箱地址已被使用 |

当调用者是 **皇帝** 角色时，`domain` 也可以是已配置 Zone 根域名下尚未创建的合法多级子域名。接口会先自动创建该子域名的 MX/SPF 记录和 D1 域名记录，再创建邮箱，并在响应中通过 `domainCreated: true` 标记本次创建了新子域名。其他角色仍只能使用现有可用域名。

### 续约邮箱

仅未过期的非永久邮箱可以续约。正数会累加到当前到期时间，`0` 会将邮箱转为永久。

```
POST /api/emails/{id}/renew
```

**请求体：**

```json
{
  "expiryTime": 86400000
}
```

**响应：**

```json
{
  "success": true,
  "id": "uuid",
  "email": "myemail@example.com",
  "expiresAt": "2026-08-06T12:00:00.000Z"
}
```

| 状态码 | 错误码 | 说明 |
|--------|--------|------|
| `400` | `invalidExpiryTime` / `expiryOverflow` | 时长无效或超出日期范围 |
| `404` | — | 邮箱不存在或不属于当前用户 |
| `409` | `emailExpired` | 邮箱已经过期 |
| `409` | `emailPermanent` | 邮箱已经永久有效 |

自动回收子域名下的邮箱续约后，其清理时间也会同步延后。

## 子域名邮箱（自动化）

> ⚠️ 仅 **皇帝** 角色可使用。

自动化创建子域名 + DNS 记录 + Email Routing + 邮箱，一步到位。

### 创建子域名邮箱

```
POST /api/emails/subdomain
```

**请求体：**

```json
{
  "domain": "moyii.de",     // 必填，基础域名（需在 KV EMAIL_DOMAINS 中）
  "prefix": "dev.newsletter", // 可选，子域名前缀，支持多级（不传则随机生成 6 位）
  "name": "hello",          // 可选，邮箱名称（不传则随机生成 8 位）
  "expiryTime": 86400000,   // 可选，邮箱过期时间（毫秒），0 或不传 = 永不过期
  "cleanupPolicy": "auto"   // 可选，auto 自动回收子域名；manual 永不自动回收
}
```

`expiryTime` 同样支持任意非负安全整数毫秒值；`0` 或不传表示永不过期。

> 注意：`/api/emails/subdomain` 默认创建 `auto` 子域名。最后一个邮箱过期后，Cleanup Worker 会在 30 分钟宽限期后清理该子域名的 DNS、KV 和 D1 记录。传入 `cleanupPolicy: "manual"` 可保留子域名并改为手动删除。

**处理流程：**

```
1. 生成子域名前缀 → dev.newsletter.moyii.de
2. 调用 DNS Worker 创建 MX + SPF 记录
3. DNS Worker 启用 Email Routing
4. DNS Worker 设置 catch-all 规则 → Email Worker
5. 子域名追加到 KV EMAIL_DOMAINS（供 generate API 使用）
6. D1 保存 domain 记录（默认 cleanupPolicy=auto）
7. D1 创建 email 记录
```

**响应（201）：**

```json
{
  "email": "hello@dev.newsletter.moyii.de",
  "emailId": "uuid",
  "subdomain": "dev.newsletter.moyii.de",
  "domainId": "uuid"
}
```

**错误响应：**

| 状态码 | 说明 |
|--------|------|
| `400` | 缺少 domain 参数 / 域名不在允许列表 / 未配置 Zone ID / 格式不正确 |
| `401` | 未登录或 API Key 无效 |
| `403` | 非皇帝角色 |
| `409` | 子域名已存在 / 邮箱地址已被使用 |
| `500` | DNS Worker 未配置 |
| `502` | DNS 记录创建失败 |

## 域名管理

> ⚠️ 需要 `MANAGE_CONFIG` 权限（皇帝角色）。

管理面板中的域名配置会同时维护三类数据：

| 数据 | 存储位置 | 用途 |
|------|----------|------|
| 根域名列表 | KV `EMAIL_DOMAINS` | 普通邮箱创建接口可选择的域名 |
| 域名 Zone 映射 | KV `EMAIL_DOMAIN_ZONES` | 创建子域名时定位 Cloudflare Zone |
| 子域名记录 | D1 `domain` 表 | 记录自动创建的子域名、DNS 记录 ID 和状态 |

### 管理面板调用流程

添加根域名时：

```
1. POST /api/domains/find-zone  查询根域名 Zone ID
2. POST /api/config             保存 emailDomains 和 domainZones
```

创建子域名时：

```
1. POST /api/domains            创建 MX/TXT 记录、启用 Email Routing、写入 D1 和 KV
2. GET /api/domains             刷新子域名列表
3. GET /api/config              刷新域名配置
```

删除子域名时：

```
1. DELETE /api/domains/{id}     删除 DNS 记录、移除 KV 域名、删除 D1 记录
2. GET /api/domains             刷新子域名列表
3. GET /api/config              刷新域名配置
```

### 获取域名列表

```
GET /api/domains?rootDomain={rootDomain}
```

**查询参数：**

| 参数 | 说明 |
|------|------|
| `rootDomain` | 可选，按根域名筛选（如 `moyii.de`），不传则返回所有域名 |

**响应：**

```json
{
  "domains": [
    {
      "id": "uuid",
      "name": "sub.example.com",
      "subdomain": "sub",
      "rootDomain": "example.com",
      "zoneId": "cf-zone-id",
      "status": "active",
      "cleanupPolicy": "manual",
      "cleanupAfter": null,
      "lastUsedAt": "2024-01-01T00:00:00.000Z",
      "mxRecordIds": "[\"id1\",\"id2\",\"id3\"]",
      "txtRecordId": "id4",
      "createdAt": "2024-01-01T00:00:00.000Z",
      "createdBy": "user-id"
    }
  ]
}
```

### 查询域名 Zone ID

管理面板添加根域名时会先调用此接口，自动查询该域名在 Cloudflare 中对应的 Zone ID。

```
POST /api/domains/find-zone
```

**请求体：**

```json
{
  "domain": "example.com"
}
```

也可以传入子域名，DNS Worker 会逐级向上查找：

```json
{
  "domain": "newsletter.example.com"
}
```

**响应：**

```json
{
  "zoneId": "cloudflare-zone-id",
  "zoneName": "example.com"
}
```

**错误响应：**

| 状态码 | 说明 |
|--------|------|
| `400` | 缺少 `domain` 参数 |
| `403` | 权限不足 |
| `404` | Cloudflare 账号下找不到对应 Zone |
| `500` | DNS Worker 未配置或查询失败 |

### 创建子域名

通过管理面板创建子域名（会同时添加到 KV EMAIL_DOMAINS 列表）。管理面板创建的子域名默认 `cleanupPolicy=manual`，不会被 Cleanup Worker 自动删除。

```
POST /api/domains
```

**请求体：**

```json
{
  "subdomain": "dev.newsletter",
  "domain": "example.com"
}
```

**字段说明：**

| 字段 | 必填 | 说明 |
|------|------|------|
| `subdomain` | 是 | 相对根域名的子域名前缀，支持 1-5 级，例如 `newsletter` 或 `dev.newsletter`，不要包含 `domain` 本身。每段只允许字母、数字、连字符，不能以连字符开头或结尾，最长 63 字符 |
| `domain` | 是 | 根域名，必须已在配置中保存 Zone ID |

**处理流程：**

```
1. 校验皇帝权限和登录状态
2. 从 KV EMAIL_DOMAIN_ZONES 读取根域名对应的 Zone ID
3. 调用 DNS Worker /provision 创建 3 条 MX 记录和 1 条 SPF TXT 记录
4. DNS Worker 启用 Email Routing 并设置 catch-all 到 Email Worker
5. 写入 D1 domain 表，保存 DNS 记录 ID，并标记为 manual 清理策略
6. 将完整子域名追加到 KV EMAIL_DOMAINS
```

**响应（201）：**

```json
{
  "id": "uuid",
  "domain": "dev.newsletter.example.com",
  "status": "active",
  "mxRecordIds": ["id1", "id2", "id3"],
  "txtRecordId": "id4"
}
```

**错误响应：**

| 状态码 | 说明 |
|--------|------|
| `400` | 缺少参数 / 子域名格式错误 / 子域名过长 / 根域名未配置 Zone ID |
| `401` | 未登录 |
| `403` | 权限不足 |
| `409` | 子域名已存在 |
| `500` | Cloudflare Token 或 DNS Worker 未配置 |
| `502` | DNS Worker 创建 DNS 记录失败 |

### 删除子域名

删除通过管理面板创建的子域名，并尽量清理其 DNS 记录。

```
DELETE /api/domains/{id}
```

**路径参数：**

| 参数 | 说明 |
|------|------|
| `id` | D1 `domain` 表中的域名记录 ID |

**处理流程：**

```
1. 读取 D1 domain 记录
2. 解析 mxRecordIds 和 txtRecordId
3. 调用 DNS Worker /deprovision 删除 DNS 记录
4. 从 KV EMAIL_DOMAINS 移除该完整子域名
5. 删除 D1 domain 记录
```

> DNS 清理失败不会阻断删除流程。接口会继续移除 KV 和 D1 记录，但 Cloudflare 上可能残留 DNS 记录，需要手动检查。

**响应：**

```json
{
  "success": true,
  "message": "子域名 dev.newsletter.example.com 已删除"
}
```

**错误响应：**

| 状态码 | 说明 |
|--------|------|
| `403` | 权限不足 |
| `404` | 域名记录不存在 |
| `500` | 删除失败 |

---

### 更新配置

```
POST /api/config
```

**请求体：**

```json
{
  "defaultRole": "civilian",
  "emailDomains": "example.com,mail.example.com",
  "adminContact": "admin@example.com",
  "maxEmails": "10",
  "registrationEnabled": true,
  "domainZones": {
    "example.com": "zone-id-1"
  },
  "turnstile": {
    "enabled": true,
    "siteKey": "0x...",
    "secretKey": "0x..."
  }
}
```

**配置说明：**

| 字段 | 说明 |
|------|------|
| `defaultRole` | 新用户默认角色：`duke` / `knight` / `civilian` |
| `emailDomains` | 可用域名列表（逗号分隔） |
| `adminContact` | 管理员联系方式 |
| `maxEmails` | 普通用户最大邮箱数量 |
| `registrationEnabled` | 是否允许新用户注册。首次运行且尚无皇帝账号时会强制允许注册 |
| `domainZones` | 域名到 Cloudflare Zone ID 的映射 |
| `turnstile` | Cloudflare Turnstile 人机验证配置 |

## 权限与角色

### 角色体系

| 角色 | 标识 | 权限 |
|------|------|------|

```
GET /api/emails/send-permission
```

**响应：**

```json
{
  "canSend": true,
  "remaining": 45,

}
```

## DNS Worker 内部接口

> ⚠️ 这些接口由 Pages App 内部调用，不对外暴露。需要 `Authorization: Bearer <DNS_WORKER_SECRET>` 认证。

### DNS Worker 基础地址

```
https://<project-name>-dns-worker.<subdomain>.workers.dev
```

---

### 创建子域名 DNS 记录

```
POST /provision
```

**请求体：**

```json
{
  "zoneId": "cloudflare-zone-id",
  "subdomain": "dev.newsletter",
  "rootDomain": "example.com"
}
```

**处理流程：**

1. 创建 3 条 MX 记录（指向 `route1/2/3.mx.cloudflare.net`）
2. 创建 1 条 SPF TXT 记录
3. 调用 `POST /zones/{zoneId}/email/routing/enable` 启用 Email Routing
4. 调用 `PUT /zones/{zoneId}/email/routing/rules/catch_all` 设置 catch-all 规则

**响应：**

```json
{
  "success": true,
  "domain": "dev.newsletter.example.com",
  "mxRecordIds": ["id1", "id2", "id3"],
  "txtRecordId": "id4",
  "emailRoutingEnabled": true,
  "catchAllSet": true
}
```

---

### 删除 DNS 记录

```
POST /deprovision
```

**请求体：**

```json
{
  "zoneId": "cloudflare-zone-id",
  "recordIds": ["id1", "id2", "id3", "id4"]
}
```

**响应：**

```json
{
  "success": true,
  "results": [
    { "id": "id1", "success": true },
    { "id": "id2", "success": true }
  ]
}
```

---

### 查找 Zone ID

根据域名自动查找对应的 Cloudflare Zone。

```
POST /find-zone
```

**请求体：**

```json
{
  "domain": "sub.example.com"
}
```

**响应：**

```json
{
  "zoneId": "cloudflare-zone-id",
  "zoneName": "example.com"
}
```

## 错误码说明

| 状态码 | 说明 |
|--------|------|
| `200` | 成功 |
| `201` | 创建成功 |
| `400` | 请求参数错误 |
| `401` | 未认证（未登录或 API Key 无效） |
| `403` | 权限不足 |
| `404` | 资源不存在 |
| `409` | 资源冲突（重复创建） |
| `500` | 服务器内部错误 |
| `502` | 上游服务错误（DNS Worker / Cloudflare API 调用失败） |

所有错误响应格式：

```json
{
  "error": "错误描述信息"
}
```
